# Product Requirements Document (PRD): Shopify Homepage Build Assignment**Company:** Troopod**Role:** AI Product Engineer---## 1. ObjectiveTake a provided HTML design prototype for a plant-based homecare brand and convert it into production-ready Shopify sections. The goal is to create sections that a merchant's marketing team can run and edit without a developer.### Provided Asset*   **File:** `purelane-homepage.html`*   **Details:** 148 KB, single file, no dependencies.*   **Note:** The prototype is not clean code and was never written with Shopify in mind.---## 2. Scope of WorkBuild the following five template sections. Getting these five right is the primary goal; everything else in the file is considered a bonus.*   **01:** Hero (`section.hero`)*   **02:** Shop / product grid (`#shop`)*   **03:** Best-selling combos (`#combos`)*   **04:** Bundles (`#bundles`)*   **05:** Reviews rail (`#reviews`)---## 3. Environment & Setup Requirements*   **Platform:** Shopify Partner account (development store).*   **Theme:** Clean install of **Dawn** (Shopify's free default theme). *Do not use a premium theme.**   **Data Seeding:** Seed the store with at least eight (8) products that suit the brand.*   **Edge Case Data Requirements:**    *   At least one product must be sold out.    *   At least one product must have no image.    *   At least one product must have a very long title.---## 4. Acceptance Criteria & Quality Standards (The Bar)The submission will be evaluated based on the following criteria:*   **Pixel-accurate:** Match the file exactly regarding layout, spacing, type, colour, and behaviour at every width from 375px up. *This is a build, not a redesign.* Rebuilding it to look how you’d have designed it is an automatic no.*   **Merchant-editable:** Nothing should be hardcoded that a marketing team would want to change.*   **Real Shopify data:** Products, prices, and content must come from the platform/Liquid. If a native field doesn't exist, solve it properly.*   **Reusable:** Code accordingly, as several sections render similar cards.*   **Survives the theme editor:** Adding, removing, reordering, and reconfiguring should never break anything, including animations.*   **Fast:** Core Web Vitals are a requirement. Treat performance as a requirement, not a cleanup task.*   **Accessible:** Must include keyboard navigation, focus states, contrast, and reduced motion considerations.*   **Clean and reviewable:** Applies to both the code and the commit history.*   **Code vs. Design Spec:** The design is the spec; the code is not. The visual output must be reproduced exactly, but the underlying HTML/CSS from the prototype should be fixed for production, semantics, accessibility, performance, and breakpoint logic. Tell the reviewer what was changed.*   **AI Usage:** Use AI however you normally would ("We build with agents here").---## 5. DeliverablesSend the following five items:1.  **Dev store URL and password.**2.  **GitHub repo** (with commit history intact).3.  **Any metafield or metaobject definitions** you created.4.  **Short notes on the build:** What you'd flag about the original file, what you changed in the code and why, and what you'd do with more time.5.  **Short notes on your AI workflow:** What you delegated, where it failed you, and what you'd systematise if you had to do twenty more of these.### Submission Instructions*   **Email to:** `nj@troopod.io`*   **Subject Line Format:** `AI Product Engineer Assignment - [Your Name]`---## 6. Timeline & Expectations*   **Deadline:** 2 days from the email that brought you to the assignment page.*   **Expectation Management:** It is not expected that all five sections will be finished. The reviewers want to see what was chosen to be done properly versus what was cut. Submit what you have and be straight about the gaps.*   **Next Steps:** Shortlisted candidates will go through a technical interview round.
